# Contribución y mantenimiento

## Flujo recomendado

1. Cree una rama para cada cambio.
2. No utilice datos reales de pacientes en desarrollo o pruebas.
3. Ejecute `npm run lint` y `npm test`.
4. Describa qué cambió, por qué y cómo se verificó.
5. Solicite revisión antes de integrar a la rama `main`.

## Convenciones

- Interfaz y mensajes en español claro.
- Campos obligatorios identificados con `*`.
- Botones descriptivos; evite textos ambiguos como “Aceptar”.
- Cualquier eliminación debe pedir confirmación.
- Los cálculos financieros e inventario deben incluir pruebas automatizadas.
- Las exportaciones nunca deben mostrar costos internos al cliente.

Use valores ficticios claramente identificados. Nunca copie un expediente real al repositorio.
